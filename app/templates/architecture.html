Indicateur de Santé Architectural

Le backend ConfiDoc respecte une architecture en couches étanches de type **Domain-Driven Design (DDD)** avec injection de dépendance. Les fichiers sont isolés de façon modulaire :

Modularité Applicative (Services / API v1 Ratio) Parfaite (DDD respecté)
  • Pas de God-Files : Les responsabilités d'extraction (OCR, parseurs) et d'anonymisation (dictionnaires, LLM) sont découpées en micro-services autonomes.
  • Couche API ultra-légère : Les routeurs FastAPI valident uniquement les types d'entrées et passent les charges de travail aux services.
  • Zéro injection SQL : SQLAlchemy 2.0 asynchrone applique un typage strict et prévient toute faille d'injection de base de données.

Middlewares de Sécurité Actifs

Ces couches de filtrage interceptent chaque requête entrante et sortante pour auditer sa provenance, mesurer les performances, forcer les en-têtes de sécurité et prévenir la ré-identification.

Middleware Classe Technique Rôle RGPD / Sécurité Statut
Audit Trail Logs AuditLogMiddleware Enregistre l'ensemble des événements de consultation documentaire pour conformité RGPD. ● ACTIF
Mesure de Latence TimingMiddleware Mesure les millisecondes de traitement pour monitorer l'efficacité OCR et IA. ● ACTIF
En-têtes de Sécurité SecurityHeadersMiddleware Injecte HSTS, CSP (Content Security Policy), et protections contre le vol de clic (Clickjacking). ● ACTIF
Traçage de Requêtes RequestIdMiddleware Génère un UUID X-Request-ID pour corréler les logs et assurer l'auditabilité. ● ACTIF
Gestion CORS CORSMiddleware Filtre les origines d'appels HTTP pour bloquer l'usage illégitime de l'API. ● ACTIF
En-têtes Proxy Réseau ProxyHeadersMiddleware Transmet proprement les IPs réelles des clients à travers les proxys Railway Edge. ● ACTIF
